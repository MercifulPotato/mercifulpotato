Item(by='iggldiggl', descendants=None, kids=None, score=None, time=1612287531, title=None, item_type='comment', url=None, parent=25999009, text='&gt; &gt; - you need to be able to open files without user interactions (no file picker), in order to open playlist, MXF or MKV files;<p>&gt; That&#x27;s what xdg portals are for: display a native file picker, pass the file descriptor. <a href="https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;desktop-integration.html" rel="nofollow">https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;desktop-integration.html</a>?...<p>This doesn&#x27;t fulfil the &quot;without user interaction&quot; bit, though, does it? The problem with those &quot;let the user pick a file and the program just gets an opaque file handle&quot;-style solutions is that they break down for any kind of file format that implicitly or explicitly consists of more than one single, atomic file that can stand for itself and doesn&#x27;t require accessing data stored in other files.<p>E.g. playlists (letting the user pick the playlist through the OS-blessed file dialogue isn&#x27;t enough, as you also need to access all media files referenced by that playlist), any kind of multi-part files (multi-part MKVs, multi-part RAR archives, whatever...), subtitles (the current expectation is that if you open a video, the video player is able to automatically find matching subtitle files stored in the same directory), locally stored HTML documents (your browser might need to load additional CSS&#x2F;JS&#x2F;images&#x2F;... and you might also want to follow any links without having to go through a file picker each time...)')
