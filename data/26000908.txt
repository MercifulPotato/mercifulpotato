Item(by='nonbirithm', descendants=None, kids=None, score=None, time=1612273831, title=None, item_type='comment', url=None, parent=25992782, text='An engine rewrite of a Japanese roguelike I played a lot[1]. I like Emacs, so I decided to see what would happen if I tried writing it in the style of what Steve Yegge calls &quot;living systems&quot;, where <i>all</i> the code is interactively callable in-game and reusable in mods. There is no scripting layer, the implementation and extension language are one and the same (Lua). I like to think of the engine as a massive programming runtime with a bunch of libraries and functions made for the sole purpose of modding the game. You could whip up a scratch buffer and start tinkering around with the game state or prototyping new mods fairly quickly.<p>The engine is not general purpose either, it&#x27;s specific to the quirks of the original game. The number of weird ideas that I could graft onto it keeps increasing with each week. Yet, without stability and feature parity with the original, it&#x27;s a long way away from having those things.<p>Another downside is going back and playing the original now isn&#x27;t as fun, because I keep thinking I&#x27;m playing the rewrite and expecting bugs to pop up at every corner. Working on a project like this for so long affects your perception of the end result in ways you can&#x27;t easily unsee.<p>Also gets pretty lonely working on something alone for years you&#x27;re not sure anyone will care about when it&#x27;s playable.<p>[1] <a href="https:&#x2F;&#x2F;github.com&#x2F;Ruin0x11&#x2F;OpenNefia" rel="nofollow">https:&#x2F;&#x2F;github.com&#x2F;Ruin0x11&#x2F;OpenNefia</a>')
