Item(by='saurik', descendants=None, kids=None, score=None, time=1612385184, title=None, item_type='comment', url=None, parent=26017453, text='I mean, the &quot;reality&quot; is that if a user uses the same password across multiple sites then they are almost certainly screwed as the entire premise that we are going to guilt all the big websites into storing hashed passwords doesn&#x27;t work for the long tail of websites that each had a high likelihood of being run by a scammer anyway. Users really just need to not use the same password across multiple websites, and that password needs to be high entropy. The recommendation of &quot;hash your stored passwords&quot; prevents you from being part of the problem, but it is a solution to the wrong problem and fails to protect either the user or the website from getting hacked: the recommendation--at least and certainly if assuming you insist on implementing login with the classic &quot;user will later send a plain text copy of their secret to the server each time they log in, which the server will (somehow) verify&quot;--absolutely should include &quot;don&#x27;t let the user generate their password&quot;, as anything else does a disservice to the user and doesn&#x27;t actually help the website. If the user is sane, they won&#x27;t care if you generate the password. If the user isn&#x27;t sane, then either 1) they are using some kind of weird deterministic scheme to generate passwords for all websites (which is frankly not optimal); 2) they are intending to use their password on another, less secure website (and so should be prevented from using that same password on your website); or 3) their password is something stupid (like their mother&#x27;s maiden name, concatenated with their date of birth... but they change the i&#x27;s to exclamation points to get around the symbol requirement).')
