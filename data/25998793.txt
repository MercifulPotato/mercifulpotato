Curried functions have their own problems because they are missing the vital parameter names. But that&#x27;s not what I meant. Think of the classic memoization example (written without a compiler at hand...)<p><pre><code>    let createMemoizer f =\n        let cache = Dictionary&lt;_,_&gt;()\n        let f&#x27; = fun x -&gt;\n            match cache.TryGetValue(x) with\n            | (true,value) -&gt; value\n            | (false, _) -&gt;\n                let result = f x\n                do cache.[x] &lt;- result\n                result\n        f&#x27;\n    </code></pre>\nThe signature is ```createMemoizer (f:&#x27;a-&gt;&#x27;b) -&gt; &#x27;a-&gt;&#x27;b```, which is not very telling, especially if it is returned by yet another function, so that even the createMemoizer name is lost. In classic OO, I&#x27;d just get a Memoizer object that carries vital documenation and what not with itself, as it is passed around. It&#x27;s no even that much longer, it&#x27;s just not as elegant to use.<p><pre><code>    class Memoizer&lt;TINPUT,TOUTPUT&gt; {\n        Dictionary&lt;T,TOUTPUT&gt; cache = new Dictionary&lt;T,TOUTPUT&gt;();\n        Func&lt;TINPUT,TOUTPUT&gt; f; \n\n        &#x2F;* ... *&#x2F;\n\n        public TOUTPUT Invoke(TINPUT parameter) {\n            if (!cache.TryGetValue(parameter, out var result)) {\n                result = f(parameter);\n                cache[parameter] = result;\n            }\n            return result;\n        }\n    }</code></pre>')
