Item(by='BigJono', descendants=None, kids=None, score=None, time=1612338243, title=None, item_type='comment', url=None, parent=26009393, text='&#x27;work&#x27; as in if you explicitly pass in undefined as a parameter to a function, the default parameter will be used in it&#x27;s stead.<p>I&#x27;ve never ever run into this because I never use undefined for anything other than stuff that&#x27;s explicitly not set, and I have no fucking idea why other people are. But I can definitely see it causing bugs if you do stuff like use &#x27;!=&#x27; everywhere and treat null and undefined as the same thing.<p>This is why the original comment is wrong. You should be narrowing your types where possible. It costs nothing to just always use null if you&#x27;re explicitly setting something, then you can use &#x27;!==&#x27; wherever you want, which means that if someone else sets something to undefined you&#x27;ll catch the bug straight away when it&#x27;s easiest to catch.<p>If you treat them the same you&#x27;re just asking for some 3rd party lib to do a &#x27;!== null&#x27; or accidentally overwrite a &quot;null&quot; with a default parameter you&#x27;re not expecting, and that&#x27;s way, way harder to troubleshoot.')
