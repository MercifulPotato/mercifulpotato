Item(by='benlivengood', descendants=None, kids=None, score=None, time=1612377929, title=None, item_type='comment', url=None, parent=26012874, text='Another option is explicit memory pools when some classes of allocation have well-defined lifetimes.  Freeing an entire pool is instant compared to either free()&#x2F;delete or GC and produces zero fragmentation.<p>For example, build parse trees in explicit pools and deallocate the whole tree and associated allocations when done with it.<p>Language support for this is fairly poor or tricky in OO languages AFAIK; but I&#x27;m mostly familiar with C++ where destructors and lack of allocator scoping (until C++11, but optional) make this a pain.  The language needs support for formally and transitively abandoning objects (or not caring, like C) to support efficient use of memory pools.')
