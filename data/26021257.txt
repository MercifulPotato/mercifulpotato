Item(by='WorldMaker', descendants=None, kids=None, score=None, time=1612399893, title=None, item_type='comment', url=None, parent=26019670, text='I&#x27;m saying it impractical to consider `null` and `undefined` as different &quot;values&quot; in JS. `undefined` was originally built to be a &quot;thrown&quot; exception built for a language without thrown exceptions. It wasn&#x27;t intended to be a placeholder value like null is. The language today makes it possible, you can today write `var x = undefined` and expect things not to blow up or behave all that differently&#x2F;quirkily between browsers and browser modes. I&#x27;m still going to be worried&#x2F;skeptical of any code that intentionally uses patterns like that of setting objects and properties explicitly to `undefined` <i>and</i> treats that as a different value from `null`.<p>Yes, you have to handle cases where things are undefined, but I&#x27;d be wary of handling them too dissimilarly to where things are null, because `undefined` was not designed to be &quot;Null 2: Electric Boogaloo&quot;, it was designed to be &quot;404 Item Not Found Exception&quot; in the time before JS had real exceptions.')
