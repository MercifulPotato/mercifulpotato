Item(by='Twisol', descendants=None, kids=[26025205], score=None, time=1612441017, title=None, item_type='comment', url=None, parent=26024655, text='The code you&#x27;ve selected is not &quot;for circles&quot;, per se. This is classic double-dispatch -- the function <i>itself</i> represents a circle (via the `x, y, r` values it closes over), and it chooses which receiver to invoke based on its identity. (The parameters in the selected function may be better named `onCircle` and `onRectangle`.)<p>If you just have a Shape, and you need to do something specific depending on the kind of Shape you have, you need some way to tell what kind of Shape you have. You can use `instanceof` and casting, but there&#x27;s no guarantee that you&#x27;ve handled all cases(^). Moreover, it&#x27;s painful in some languages (like Java) to extract the subclass-specific fields, as you need to rebind the value to a new variable of the right type first.<p>The Visitor pattern is a classic object-oriented solution to this problem, typically using double dispatch. The Shape itself knows what kind of shape it is, so rather than asking it what type it is, you provide it a set of _strategies_ (no relation to the Strategy pattern), one for each type of Shape. The Shape doesn&#x27;t know what you want to do with it, so it calls you right back, invoking the circle- or rectangle-specific logic depending on what kind of shape it is. (Hence, double-dispatch.)<p>Gabriel (OP) observes that the Visitor pattern is exactly the Boehm-Berarducci encoding of a sum type. The Visitor pattern is very common in OO programming (see, for instance, abstract syntax trees), so the fact that we&#x27;re so often using an encoding of a more direct concept is worth remarking on. I know I&#x27;d much rather use sum types in general than use the Visitor pattern.<p>(^) As an aside, I&#x27;ve never found &quot;Shape&quot; to be a very convincing example of sum types, as it&#x27;s much easier to imagine as an open family than as a closed family. In an open family of shapes, there is no &quot;all cases&quot;, and instanceof&#x2F;casting is inappropriate from the beginning. I think object algebras (see my other comment) give a more motivating class of examples of closed families, including ASTs.')
