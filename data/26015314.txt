Item(by='jerf', descendants=None, kids=[26016170], score=None, time=1612369935, title=None, item_type='comment', url=None, parent=26013273, text='This sort of thing is why I&#x27;m generally not impressed by the perennial &quot;GC vs. manual memory management&quot; debate. Manual memory management usually isn&#x27;t. Simply using &quot;malloc&quot; isn&#x27;t manual memory management, there&#x27;s still a lot of stuff going on behind the scenes that may or may not match your program&#x27;s use case. Both GC and &quot;manual&quot; memory management aren&#x27;t single points, they&#x27;re suites of options, which you can often mix and match beyond that. Statements like &quot;Manual memory management is better than GC&quot; is roughly like saying &quot;Pie tastes better than cake!&quot;... it doesn&#x27;t even really make <i>sense</i>, there&#x27;s so many pies and so many cakes that there&#x27;s no way to universally order them like that, even for a specific person; add in the subjectivity of taste (in this metaphor, the different needs various programs have of memory in the first place) and it&#x27;s beyond absurd.<p>(To my mind, &quot;manual memory management&quot; is when you get a big slab of memory from something, doesn&#x27;t much matter what, and <i>everything else</i> is managed in your application code. If you&#x27;re not doing that, you&#x27;ve got some sort of &quot;automation&quot; involved, and that automation can mismatch your program&#x27;s memory needs every bit as much as a &quot;GC&quot; can.)')
