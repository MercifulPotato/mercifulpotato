Item(by='matwood', descendants=None, kids=[26025462, 26025231], score=None, time=1612445261, title=None, item_type='comment', url=None, parent=26025013, text='There are a few reasons why doing things like this in the RDBMS is a good thing for many use cases.<p>First, there is a ton of already built tooling for dealing with an RDBMS. This alone is why I think every project should default to using an RDBMS and only move if a good case can be made.<p>Second, like it or not, sql is the defacto language for querying the data. After 20+ years of writing software, I&#x27;ve used many languages, but sql (of course it has evolved) has been a constant across RDBMS. I&#x27;ve seen many service layers and front ends change over the years, all while sitting on the same RDBMS. Given the speed at which tech moves, it&#x27;s pretty amazing when you think about it.<p>Finally, for things like graphs or json, it&#x27;s often the case that I only need handle it <i>in addition</i> to my existing relational datastore. In some cases it might make sense to stand up an entire system for the use case (like a solr server for document searching), but many times I just need to store a bit of json or I have one or two graphs that need to be represented. In these cases, standing up an entire separate system adds unneeded complexity.')
