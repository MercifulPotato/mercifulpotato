Item(by='kaba0', descendants=None, kids=[26005258, 26004720, 26004506, 26004279], score=None, time=1612288256, title=None, item_type='comment', url=None, parent=26001972, text='I don’t have much knowledge on the low-level intricacies of CPUs, could someone please answer a question of mine? \nThere is an older, famous post titled something like “C is not a low-level language”, and relatedly one that assembly itself is not all that low-level today.<p>I do now almost nothing about the state of today’s CPUs, only that they are extensively complex with long pipelines and that branch prediction is a thing. Also, several layers of caches. x86 on top is almost only an API which frees the hardware engineers from backward compatibility, since these intricacies are programmed by microcodes that are not really accessible to general software.<p>My question is, wouldn’t a “dumber” processor be better with a more expressive “API”, with instructions like prefetch, some form of parallelism (so that pipelines can be created with machine code and not just heuristics), since it is probably easier and better to branch predict in software than in hardware? In a way current processors sort of JIT compile assembly to some hardware-native form, but if those hardware-level tools were accessible to software, software could do much much better optimizations and bugs could be patched.')
