Item(by='Jtsummers', descendants=None, kids=[26020680], score=None, time=1612394148, title=None, item_type='comment', url=None, parent=26020283, text='My Go is very rusty so I was spending some time refreshing my memory on the empty interface.<p>As I understand it, in the worst case that Go&#x27;s generics are implemented with boxed types and a pretty wrapper around the empty interface, you end up with equivalent performance to today but with clearer code (within functions, function declarations becoming somewhat more complicated but not excessively so).<p>But in the best case, this information being given to the compiler will give you clearer code (same qualifications as previous paragraph) and better performance as run-time type verification is moved to compile-time.<p>I suppose if you never use the existing workaround (empty interfaces), then there&#x27;s no benefit to you in having generics available. But if you do, it seems to me that you&#x27;re going to get <i>some</i> benefit.')
