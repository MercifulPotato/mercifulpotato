Item(by='georgewfraser', descendants=None, kids=[26021533], score=None, time=1612390016, title=None, item_type='comment', url=None, parent=26019184, text='The main benefit of a columnar representation in <i>memory</i> is it&#x27;s more cache friendly for a typical analytical workload. For example, if I have a dataframe:<p><pre><code>  (A int, B int, C int, D int)\n</code></pre>\nAnd I write:<p><pre><code>  A + B\n</code></pre>\nIn a columnar representation, all the As are next to each other, and all the Bs are next to each other, so the process of (A and B in memory) =&gt; (A and B in CPU registers) =&gt; (addition) =&gt; (A + B result back to memory) will be a lot more efficient.<p>In a row-oriented representation like protobuf, all your C and D values are going to get dragged into the CPU registers alongside the A and B values that you actually want.<p>Column-oriented representation is also more friendly to SIMD CPU instructions. You can still use SIMD with a row-oriented representation, but you have to use gather-scatter operations which makes the whole thing less efficient.')
