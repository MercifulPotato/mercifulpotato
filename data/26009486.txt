Item(by='Jasper_', descendants=None, kids=[26010215, 26009716, 26010786], score=None, time=1612315304, title=None, item_type='comment', url=None, parent=26003525, text='The typical convention these days is:<p>- &#x2F;usr&#x2F; is read-only data. &#x2F;usr&#x2F;bin&#x2F; contains OS-supplied binaries, &#x2F;usr&#x2F;lib&#x2F; contains OS-supplied libraries.<p>- &#x2F;var&#x2F; is read-write state data and will persist between boots. &#x2F;var&#x2F;log&#x2F; is for log files.<p>- &#x2F;run&#x2F; is read-write scratch on a tmpfs, and will be cleaned up between boots. So, UNIX sockets and other temporary files go here.<p>- &#x2F;etc&#x2F; is per-system configuration overrides. There is a goal to move to &quot;empty &#x2F;etc&#x2F;&quot;, meaning you should be able to remove all files in &#x2F;etc&#x2F; and still have a functioning system.<p>- &#x2F;opt&#x2F; is &quot;vendor space&quot;. The OS should never touch &#x2F;opt&#x2F;.<p>The names are weird, but that&#x27;s the intention behind the new scheme. If you want to change configuration, the default config might be shipped read-only in &#x2F;usr&#x2F;, but it should be overridable in &#x2F;etc&#x2F;. This is why systemd ships read-only unit files in &#x2F;usr&#x2F;, which are symlinked into &#x2F;etc&#x2F; to be &quot;enabled&quot;.')
