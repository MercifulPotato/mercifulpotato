Item(by='onei', descendants=None, kids=[26001568], score=None, time=1612257820, title=None, item_type='comment', url=None, parent=25993451, text='You missed my point. Ubuntu packages pip via apt, not via pypi. You can swap from an installation provided by apt to one provided by pypi using your method, but it means you&#x27;re off the supported version and any guarantees of support are lost. The quick fix here is to not update pip to the latest, but the latest supported by python3.5 and carry on with your migration as scheduled.<p>I realise that this is a common practice, and I&#x27;ve been caught out myself in the past with CentOS7+Python3.4, but be aware that it comes with its own set of tradeoffs. Sadly, the packaged version of pip is usually quite old and pip is loud about outdated versions, so the solution is either to upgrade the OS or leverage something that is not as tied to the OS.<p>If you want to explore the latter, I&#x27;d suggest python:3.5 containers if you&#x27;re building pure python code. Alternatively, I&#x27;d suggest manylinux containers if you have C extensions and run on a glibc distro like Debian&#x2F;RHEL. Both will have the last supported version of pip for your python version installed and neither will randomly break on you.<p>The final lesson I&#x27;ve learned is to be aware that pip can install the latest version supported by your python version as long as it can access the metadata for the package in the index. That&#x27;s available on pypi, but not all self-hosted indexes have it, notably nexus.')
