Item(by='repsilat', descendants=None, kids=None, score=None, time=1612415979, title=None, item_type='comment', url=None, parent=26021533, text='To rephrase the sibling comment, if you had an array of four {ABCD} structs, there&#x27;s basically two ways of storing them on disk:<p>1. AAAA BBBB CCCC DDDD<p>2. ABCD ABCD ABCD ABCD<p>One major heuristic in how CPUs make your code fast is to assume that if you access some memory, you&#x27;re probably interested in the memory nearby. So when you access the first &quot;A&quot;  bit of memory (common to both sequences above), depending on the memory layout you use, the CPU might also be smart and load the next bits into memory too -- maybe the next &quot;AA&quot;, maybe &quot;BC&quot;.<p>Depending on your workload, one or the other of those might be faster. If you&#x27;re only interested in the first ABCD element because you&#x27;re doing<p><pre><code>  SELECT * FROM users WHERE id=$1\n</code></pre>\nthen you&#x27;ll likely want &quot;row-oriented&quot; data -- the #2 scheme above. But if you&#x27;re interested in all of the A values and none of the values from B&#x2F;C&#x2F;D because you&#x27;re doing<p><pre><code>  SELECT AVG(age) FROM users\n</code></pre>\nthen you&#x27;ll likely want something &quot;column-oriented&quot; -- the #1 scheme above.')
