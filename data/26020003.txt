This is a bottom-up approach - how do we get pixels on screen?<p>Other approaches start from &quot;how do we represent a scene&quot;, in the sense of a scene graph or at least lists of vertices, triangle indices, and textures. That cuts the problem into &quot;represent scene&quot; and &quot;render scene&quot;. That&#x27;s a practical division, because that&#x27;s the interface between what you put into a renderer and what the renderer does with it. Today, you&#x27;re either using someone else&#x27;s rendering system, or you&#x27;re building the rendering system. Probably not both, except as an exercise.<p>This division is actually a bit above the OpenGL&#x2F;Vulkan level. Vulkan is complicated because it&#x27;s mostly about setting up the GPU to run a rendering pipeline, talk to displays, and other housekeeping. And memory management. If you have a library to manage that part, it&#x27;s not so bad.<p>It&#x27;s like old computer books, where you started out learning what the arithmetic&#x2F;logic unit (the ALU) did, how it interacted with memory, what the instruction decoder did, and so on. This prepared you for assembly language programming. Few courses start out there today.<p>Incidentally, the caption for figure 12-1 is missing some symbols. It reads  &quot;Using instead of doesn’t produce the results we expect.&quot;')
