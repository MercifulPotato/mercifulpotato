Item(by='marcan_42', descendants=None, kids=[25997753], score=None, time=1612235933, title=None, item_type='comment', url=None, parent=25996861, text='The goal of the Asahi Linux project is to develop clean, maintainable, upstreamed, first-class support for Apple Silicon on Linux, that works as well or better than Linux on x86. From the beginning I said we weren&#x27;t going for a tech demo, but for the long-term product.<p>We are also documenting the hardware here: <a href="https:&#x2F;&#x2F;github.com&#x2F;AsahiLinux&#x2F;docs&#x2F;wiki" rel="nofollow">https:&#x2F;&#x2F;github.com&#x2F;AsahiLinux&#x2F;docs&#x2F;wiki</a><p>I don&#x27;t know what Corellium&#x27;s goal is, since it isn&#x27;t clear what they get out of this as a company other than PR, nor have they interacted with the open source community in any way whatsoever to date (I publicly invited them to our IRC channels and they&#x27;ve yet to show up), nor attempted to upstream any of their work (a third party has and that didn&#x27;t go so well for the first version). They seem to be going for the tech demos and PR angle, judging by their actions and codebase so far :)<p>E.g I spent most of Saturday debugging the source of L2 memory subsystem bus error exceptions in our bootloader, m1n1. Corellium&#x27;s codebase and preloader just turns off reporting those errors entirely, all the way into Linux. There are very, very different approaches going on here.<p>FWIW, Corellium had been developing their kernel in secret for A14 devices (that&#x27;s the extremely similar iPhone version of the M1) for months now, plus had previous versions for older Apple SoCs, so it&#x27;s not like they did this in two weeks; rather that they are currently piecewise releasing and adapting code they&#x27;ve had for a while and developed on jailbroken devices, while we&#x2F;Asahi Linux started from scratch mid-January when Apple finally published the tools to run your own kernels on M1 Macs.<p>I&#x27;m happy to pull any drivers they develop and release that are clean and upstreamable, but we&#x27;re working step by step and I&#x27;m not in a race with them; we&#x27;re in this for the long run and I want to make sure anything we work on is the right way of doing things.<p>We&#x27;re also working on GPU acceleration, which is a hard requirement for a usable desktop, and which as far as I know Corellium have nothing on. Alyssa is working on the userspace side already; I&#x27;ll jump on the kernel side as soon as the necessary kernel dependencies are in.<p>I&#x27;m currently writing a quick start guide to help other kernel devs with interest get started with development, and in the coming weeks I will be taking some time to develop an open hardware design for a serial debug cable for these machines, and building some prototypes to send to other kernel devs to help bootstrap community members who want to help. Today I&#x27;m also working on using one M1 machine as a serial terminal for another, with a standard type C cable (it should be possible AIUI, but I need to reverse engineer some details to get the right commands sent to the Type C controller) - not the cheapest solution but certainly the lowest effort one right now, if you have the money for two M1 boxes.')
