Item(by='maliker', descendants=None, kids=None, score=None, time=1612446679, title=None, item_type='comment', url=None, parent=26024783, text='My ELI7 understanding is that python installs required modules (libraries) at the system level by default, and doesn&#x27;t have good support for installing modules into local directories like node&#x2F;C&#x2F;java&#x2F;etc. does, which leads to conflicts. Users have to find a set of modules that support all of the scripts on their system. The current workaround is to isolate each script&#x27;s requirements, but there are a ton of competing tools to do this (virtualenv, pipenv, poetry, etc.), so it&#x27;s hard to choose the &quot;best&quot; isolation solution.<p>One reason people like PEP 582 is that, by being something built into the interpreter, it will reduce a lot of the confusion over which isolation tool to use.<p>Part of the problem, which local installs won&#x27;t completely solve, is that the python interpreter is still changing fast enough that modules are having trouble keeping up. E.g. tensorflow is still working on python3.9 support [1], and now we&#x27;ll see python3.10 in the next couple weeks. Even with local installs we&#x27;ll have to be careful to use the right interpreter.<p>Another piece of the problem, which is also kind of a good thing, is the huge size of the python module ecosystem. I&#x27;ve got python scripts with over a hundred requirements. It saves me from writing a lot of code, but resolving the requirements is a challenge. The pip package manager has recently added a dependency resolver, which has helped a little make sure everything can work together.<p>The only surefire ways I can think of to make this huge module ecosystem interoperate cleanly are (1) have every module support every other version of every other module and interpreter (insane amount of work, won&#x27;t happen) or (2) have simpler interop interfaces like the unix shell convention of only passing strings between programs, but that would take away a lot of the ease-of-use of passing rich objects around between modules.<p>[1] <a href="https:&#x2F;&#x2F;github.com&#x2F;tensorflow&#x2F;tensorflow&#x2F;issues&#x2F;44485" rel="nofollow">https:&#x2F;&#x2F;github.com&#x2F;tensorflow&#x2F;tensorflow&#x2F;issues&#x2F;44485</a>')
