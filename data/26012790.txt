Item(by='mantap', descendants=None, kids=None, score=None, time=1612352990, title=None, item_type='comment', url=None, parent=26008542, text='It&#x27;s funny, I have a policy of the opposite. Use undefined, don&#x27;t propagate null.<p>map.get(&quot;missingKey&quot;) returns undefined.<p>The new ?. operator returns undefined, even if you pass it null.<p>Undefined means that you don&#x27;t have to care about the difference between { foo: undefined } and { }.<p>The only pain point is that JSON.parse() produces null, but this is relatively easy to work around.<p>I don&#x27;t find any reason to ever produce a null. I just treat it as a value that can occur when using certain APIs.<p>If your code depends on the difference between a missing key and a missing value, probably you should be using a Map which makes that difference explicit with separate set() and delete() methods.')
