Item(by='mikepurvis', descendants=None, kids=None, score=None, time=1612277490, title=None, item_type='comment', url=None, parent=25998884, text='Interestingly, pip 21.0 <i>is</i> marked on pypi as Python 3.6 only:<p><a href="https:&#x2F;&#x2F;pypi.org&#x2F;project&#x2F;pip&#x2F;21.0&#x2F;" rel="nofollow">https:&#x2F;&#x2F;pypi.org&#x2F;project&#x2F;pip&#x2F;21.0&#x2F;</a><p>So I wondered if there was an issue here where pip 8.1.1 is just so old that it doesn&#x27;t know how to respect that constraint? As an experiment, I started with a new venv and upgraded just to the latest pip 20:<p><pre><code>    $ test&#x2F;bin&#x2F;pip install pip==20.3.4\n    Collecting pip==20.3.4\n      Downloading https:&#x2F;&#x2F;files.pythonhosted.org&#x2F;packages&#x2F;27&#x2F;79&#x2F;8a850fe3496446ff0d584327ae44e7500daf6764ca1a382d2d02789accf7&#x2F;pip-20.3.4-py2.py3-none-any.whl (1.5MB)\n        100% |################################| 1.5MB 695kB&#x2F;s\n    Installing collected packages: pip\n      Found existing installation: pip 8.1.1\n        Uninstalling pip-8.1.1:\n          Successfully uninstalled pip-8.1.1\n    Successfully installed pip-20.3.4\n    You are using pip version 20.3.4, however version 21.0.1 is available.\n    You should consider upgrading via the &#x27;pip install --upgrade pip&#x27; command.  \n</code></pre>\nNow interestingly I don&#x27;t get any prompts after that, and it doesn&#x27;t try to upgrade past 20.3, so I think that might have been the last gasp of pip 8.1.1:<p><pre><code>    $ test&#x2F;bin&#x2F;pip install -U pip\n    DEPRECATION: Python 3.5 reached the end of its life on September 13th, 2020. Please upgrade your Python as Python 3.5 is no longer maintained. pip 21.0 will drop support for Python 3.5 in January 2021. pip 21.0 will remove support for this functionality.\n    Requirement already satisfied: pip in .&#x2F;test&#x2F;lib&#x2F;python3.5&#x2F;site-packages (20.3.4)\n    Collecting pip\n      Using cached pip-20.3.4-py2.py3-none-any.whl (1.5 MB)\n      Using cached pip-20.3.3-py2.py3-none-any.whl (1.5 MB)\n</code></pre>\nSo yeah, basically the fix is just to hard-code the version you know works. But I think this demonstrates an issue with the PyPA being out of touch with real-world use-cases. No one is upgrading pip version by version— 99% of pip installations are either going to be get-pip.py or upgrading a venv directly from a distro-shipped version. IMO those use-cases should be carefully tested on each release and checked for the versions in popular distros, even at the tail end of the support windows.<p>The other side of this is Debian&#x2F;Ubuntu, of course, and with sufficient coordination (knowing the a pip was coming which their &quot;supported&quot; pip would auto-upgrade to and break itself) they could have patched their `python3-pip` package to only upgrade as far as 20.3.4.')
