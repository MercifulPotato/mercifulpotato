Item(by='bitwize', descendants=None, kids=[26004686, 26005158], score=None, time=1612286174, title=None, item_type='comment', url=None, parent=26001918, text='&gt; Wayland&#x27;s biggest mistakes were not launching with a coherent strategy for replicating functionality like screen sharing, screenshots, and to a lesser extent remote desktop&#x2F;applications.<p>It&#x27;s not just about replicating this functionality. It&#x27;s about having an open framework that makes building these tools, and other unforeseen tools, easy. X11 was very accommodating of this.<p>For example, I like to run xsnow during the holidays. Wayland&#x27;s answer to xsnow is -- we don&#x27;t support that, but tell you what, draw up an RFC for a D-Bus API for desktop snow and wait 5-7 years for compositor implementors to consider incorporating it. Or something completely different. You know, whatever. It&#x27;s like you have to prove your use case is valid to the community before you can even start hacking on it in a way that you can expect it to work with more than one DE.<p>For Wayland the attitude is &quot;Fuck you. You get a buffer for a desktop window and that&#x27;s it. [Wayland does not support nested windows.] Oh, that&#x27;s not enough? You&#x27;re not <i>writing</i> a desktop app? You want snow on the desktop&#x2F;a desktop magnifier&#x2F;a hall of mirrors effect toy&#x2F;an anime window sitter&#x2F;pinnable menus&#x2F;something that responds to global hotkeys&#x2F;etc.? I&#x27;m sorry, did we not anticipate your pwecious widdle use case? Fuck you. No one actually writes applications that way any more, <i>nerd</i>. Go back to the nerd table. We&#x27;re trying to get the cool popular Mac-using kids to notice us here.&quot;<p>The X11 security issues are mitigatable with some changes to the server implementation. The Wayland approach really never was about security. It&#x27;s about letting the cool kids define the shape of the Linux desktop to the exclusion of ordinary users&#x2F;hackers.')
