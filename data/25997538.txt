Item(by='cromwellian', descendants=None, kids=None, score=None, time=1612241266, title=None, item_type='comment', url=None, parent=25997215, text='It may not currently be enforced, but the compiler could enforce it, depending on assumptions, the same way we enforced it on the GWT compiler (of which I&#x27;m one of the engineers who worked on it)<p>With GWT, we had global information, so we could promote methods to static by class hierarchy analysis.<p>For a Kotlin class, even with dynamic loading, if the class is not marked &#x27;open&#x27;, final methods not implementing an interface, or private methods, can be converted into static methods.<p>e.g.<p><pre><code>   class A(val x: Int) {\n     fun print() = x\n   }\n</code></pre>\ncan be transformed into<p><pre><code>   class A(val x: Int) {\n     fun print() = printStatic(x)\n     companion object {\n       fun printStatic(self: A) = self.x\n     }\n   }\n\n</code></pre>\nAnd any call site with access to the original signature, e.g.<p><pre><code>   val a = A()\n   println(a.print())\n\n</code></pre>\ncould be rewritten safely as<p><pre><code>   val a = A()\n   println(A.printStatic(a))\n\n</code></pre>\nNow, the current Kotlin compiler frontend or backend may not do any of these, but it could.<p>There&#x27;s nothing in the compiler language itself that blocks such optimizations, especially if you&#x27;re willing to limit reflection (as is the case with Kotlin MPP code), or admit a LTO pass.')
