Item(by='cyphar', descendants=None, kids=[26022004], score=None, time=1612405312, title=None, item_type='comment', url=None, parent=26007428, text='Yeah, sending SIGKILL to pid1 of a container will insta-kill the whole thing. But the network resource stuff does also include removing iptables rules, so it&#x27;s not something that you really want to be skipping. It feels like the network resources being cleaned up should be a background job rather than blocking the kill (after all, it&#x27;s not critical to stopping the container and most resources will be freed by the network namespace dying). Also (if you&#x27;re not already aware of this), you should note that if you use &quot;docker exec&quot; or share pid namespaces between containers, this trick will no longer work because your saved pid is not the pid1 of the namespace (runc has a &quot;kill everything in the container&quot; mode to work around this -- so I&#x27;d suggest using &quot;runc kill SIGKILL&quot; rather than doing it manually but it&#x27;s probably not that important).<p>Have you opened a bug report in Docker upstream to see if they can improve the situation (perhaps by putting networking cleanup jobs to a background goroutine)?')
