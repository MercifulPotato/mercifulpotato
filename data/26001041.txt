Item(by='quotemstr', descendants=None, kids=[26001723], score=None, time=1612274727, title=None, item_type='comment', url=None, parent=25999623, text='&gt; Go devs, saying that it was technically impractical due to some of Go&#x27;s requirements not matching the libc&#x27;s semantics.<p>I&#x27;ve always considered claims like this to be bullshit. I&#x27;ve worked a lot with both libc level system calls and (for crash report generation) direct system calls bypassing libc. They&#x27;re the same interface. There&#x27;s nothing you can do with a raw system call interface that you can&#x27;t do through raw libc --- with rare exceptions for things like libc not having system call wrappers for some new system call or legacy ill-advised emulation like in fallocate. None of these exceptions is a justification for bypassing libc for calling open(2) or write(2).<p>As far as I can tell, the real reason Go eschewed libc system call interfaces is that the Go developers want to think of themselves as &quot;not C&quot;.')
