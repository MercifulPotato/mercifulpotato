Item(by='throwanem', descendants=None, kids=None, score=None, time=1612299049, title=None, item_type='comment', url=None, parent=26006259, text='Yeah, I mean I don&#x27;t want to just say &quot;you&#x27;re wrong&quot;, but you kind of are here.<p>TypeScript alone doesn&#x27;t make any assertions and doesn&#x27;t offer any checking at system boundaries (&quot;external inputs&quot;). That&#x27;s not what it is for, and the types you specify with it aren&#x27;t objects. All that stuff gets compiled out before the code is even run. The point of TypeScript is so that you don&#x27;t <i>have</i> to run your code to know whether the way it handles data internally is the way you intend it to.<p>Validation at system boundaries is a separate concern, and handled separately. I like to do it with a package called &quot;runtypes&quot;, which both supports arbitrarily complex shapes in its validators, and expresses them in a way that&#x27;s very close to TS and can be trivially converted into compile-time TS types so that you don&#x27;t have to write the same types twice.<p>I wasn&#x27;t sure what to make of TypeScript for a while, too. But having once tried it, and since become very conversant with it, I&#x27;ll go back only for trivial tasks or under significant duress. Sure, writing types is a fair bit more work up front and a little more ongoing, but it really does make a huge difference in maintainability; in my experience, it&#x27;s a little work now to save a <i>lot</i> of work later, as the resulting code is both less likely to exhibit an entire class of often quite subtle bugs, and easier to reason about and modify.')
