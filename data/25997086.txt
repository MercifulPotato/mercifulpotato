Item(by='cromwellian', descendants=None, kids=[25997215], score=None, time=1612235665, title=None, item_type='comment', url=None, parent=25990585, text='Kotlin methods are final by default unless marked open, and thus nonpolymorphic dispatch unless through an interface.<p>It sounds to me like the problem isn’t the VM it’s the insane amount of framework code you have to be initialized. This can be optimized with Java via class data sharing and snapshotting but if your code is all written in Kotlin and you toss Spring into the trash can In favor of say, Dagger or hand crafted DI, most of your problems would go away.<p>Besides, Kotlin&#x2F;Native can compile and run without a VM.<p>See <a href="https:&#x2F;&#x2F;august.nagro.us&#x2F;jvm-startup.html" rel="nofollow">https:&#x2F;&#x2F;august.nagro.us&#x2F;jvm-startup.html</a> for examples of how to optimize startup without Prewarming JIT.')
