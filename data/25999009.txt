There are practical and technological means to address most of these concerns, though it would require some work. Admittedly, I have a very Linux-focused perspective. So here we go, as the devil&#x27;s advocate:<p>&gt; - you need to be able to open files without user interactions (no file picker), in order to open playlist, MXF or MKV files;<p>&gt; - you need raw access to &#x2F;dev&#x2F;* to play DVD, CD and other optical disk (and the equivalent on Windows);<p>&gt; - you need ioctl on such devices, to pass the MMC for DVD&#x2F;Bluray;<p>That&#x27;s what xdg portals are for: display a native file picker, pass the file descriptor. <a href="https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;desktop-integration.html?highlight=theme#portals" rel="nofollow">https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;desktop-integration.html?...</a><p>&gt; - you need the same if ever you have a database of files (media center oriented);<p>Well, portals can also punch holes selectively to select a folder, I think. Plus, the database can sit inside the sandbox.<p>&gt; - you need raw access to &#x2F;dev&#x2F;v4l* for your webcams and be able to control them;<p>Pipewire should sidestep that issue, though it<p>&gt; - you need access to the GPU stack, which is running in kernel-mode, btw, to output video and get hw acceleration;<p>&gt; - you need access to the audio stack, also in low-level mode;<p>&gt; - you need access to the DSP acceleration (not always the GPU);<p>&gt; - on linux, you have access to x11 for the 3 above features, which is almost root;<p>Wayland is here to stay. You just need access to DRI, which is a common use-case with flatpak&#x2F;DRI. Admittedly, I know nothing about DSP interfaces. Not sure why you&#x27;d need low-level access to the audio stack, and not just pipewire or pulseaudio.<p>&gt; - you need access to the system settings to disable screensavers, and adjust brightness;<p>&gt; - you need to expose an IPC (think MPRIS on Linux);<p>All of this is handled via d-bus or portals (inhibitors, MPRIS), so fine for flatpaks.<p>&gt; - you need to unzip, untar, decrypt, decipher and so on;<p>Usually provided as part of the Flatpak runtime.<p>&gt; - you need access to mounts to be able to see the insertion of DVD&#x2F;Bluray&#x2F;USB&#x2F;SD cards and such;<p>Well, desktop environments usually offer to open new devices with vlc. That could be a lost feature, but I didn&#x27;t even know it was there.<p>&gt; - many OpenGL client libraries need access to the &#x2F;etc too;<p>Not sure about this one. Do they? What for? Couldn&#x27;t a sandboxed &#x2F;etc do?<p>&gt; - you need access to the network, as input and output (think remote control);<p>Yes, you&#x27;re right, that&#x27;s one extra permission. I wish it was possible to ask for it at runtime with flatpak, on first use. I don&#x27;t think even Android supports asking for this at run-time.<p>&gt; - you need access to &#x2F;etc&#x2F; (registry) for proxy informations, fonts configuration and accessibility;<p>&gt; - you need access to the fonts and the fonts configuration (see fontconfig).<p>Proxy information is provided via a portal that should be automatically used by Qt: <a href="https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;portal-api-reference.html?highlight=proxy#gdbus-org.freedesktop.portal.ProxyResolver" rel="nofollow">https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;portal-api-reference.html...</a><p>Theming is handled as runtime extensions, though I admit it&#x27;s often broken (OK, most theming is broken for me under sway as I didn&#x27;t bother setting it up: <a href="https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;desktop-integration.html?highlight=theme#theming" rel="nofollow">https:&#x2F;&#x2F;docs.flatpak.org&#x2F;en&#x2F;latest&#x2F;desktop-integration.html?...</a><p>No idea about accessibility.<p>--<p>It looks like some progress is being made on flathub, though it still needs filesystem access, notably for subtitle files: <a href="https:&#x2F;&#x2F;github.com&#x2F;flathub&#x2F;org.videolan.VLC&#x2F;issues&#x2F;108" rel="nofollow">https:&#x2F;&#x2F;github.com&#x2F;flathub&#x2F;org.videolan.VLC&#x2F;issues&#x2F;108</a>')
