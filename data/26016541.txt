Item(by='dehrmann', descendants=None, kids=None, score=None, time=1612374535, title=None, item_type='comment', url=None, parent=26015096, text='As others have said, use scrypt, but...<p>PBKDF2, obviously a less marketable name than scrypt, was a pretty standard tool for dealing with fast hash functions. What turned out to be a bigger problem than speed is memory use. Now that we have widespread GPUs, it&#x27;s a lot easier to parallelize password cracking, and most cryptographic hash functions use negligible memory, so it parallelizes very well. scrypt also improves this.<p>I actually saw scrypt take down a website. It got attacked with brute-force password attempts (&lt;100k, so it wasn&#x27;t a serious attack), and the scrypt calls exhausted the CPU, essentially doing a DoS attack. We ended up wrapping the call in a semaphore to prevent this. You don&#x27;t normally think about it, but login might be the most expensive operation your webserver does.')
