Item(by='danShumway', descendants=None, kids=None, score=None, time=1612423863, title=None, item_type='comment', url=None, parent=26022860, text='&gt; perhaps increasing opportunities for abuse will also greatly popularise JS whitelisting<p>I default-block JS on sites I visit, but I still want JS to be safer, and I want the new feature proposals to avoid making security worse. I am skeptical that accelerationism is a good strategy that we should be encouraging for web security.<p>Let me expand on that instead of being dismissive. Part of the reason why I don&#x27;t think it&#x27;s a good strategy to purposefully make JS dangerous so people are more careful about it is that I&#x27;m not sure what the end goal of that plan is. Say you succeed, and everyone becomes scared to run JS code on a website. Okay, great, but now what? Popularizing JS-blockers is one thing, but for all of the criticism about the web, online apps satisfy a need that no other application platform does. There is no other general application platform where it&#x27;s mostly safe to run random untrusted code, and users <i>really</i> want a platform where they can do that.<p>I default-block JS because I don&#x27;t currently trust the browser mechanisms that exist today to protect my privacy&#x2F;security in all cases. But I want to eventually trust them. I want JS to get more secure over time, not less -- I&#x27;d like to eventually live in a world where I&#x27;m not default-blocking JS at all. Blocking JS is a cudgel; if the language is too insecure, then it just becomes unsafe to ever enable it in any context.<p>And sure, I understand that at least a few people on HN would love a JS-free web, and I do get where they&#x27;re coming from, but I&#x27;ve never heard a good (and feasible) proposal from those people about what can replace the web as an app environment. Some theories, occasionally, but nothing with momentum that I think is likely to succeed. And what we have -- both native environments and phones -- none of them are safe enough where you&#x27;d feel comfortable executing random unvetted code dozens or hundreds of times every day. Virtually all of them are easier to fingerprint, native Linux security right now is a disaster, iOS is getting <i>better</i>, but it&#x27;s still not great. You&#x27;d be foolish to install a dozen iOS apps every day. And we have the extra problem that a nontrivial portion of iOS&#x27;s security comes at the cost of Apple waging (imo) a low-key war against general purpose computing and user control over their own devices.<p>I occasionally hear people say that we shouldn&#x27;t try to create a safe web-like application runtime at all, they say people should just vet all the code the run. But I don&#x27;t think that&#x27;s a realistic position to take. Users don&#x27;t want to think about a link to an application before they click on it, and to be honest, it is genuinely kind of crappy that they need to. There&#x27;s a very clear reason why all of us would want to be able to see a cool app and just immediately run it without worrying that it&#x27;ll install malware. And users want both that security and the freedom to publish any content or code that they create without going through gatekeepers. For better or worse, there&#x27;s nothing else that gets as close to that as the web right now, and I am loathe to get rid of that just so I can encourage users to be a little bit more cautious about the existing privacy&#x2F;security risks in JS today.<p>So before we purposefully make JS less safe so that more people will block it, I&#x27;d like to hear what the actual end game is, and I&#x27;d like to hear what the alternative platform is going to be and how people plan to secure it. Absent some kind of concrete, realistic proposal with momentum behind it, I want to make JS more secure&#x2F;private, not less.')
