Item(by='yoavm', descendants=None, kids=None, score=None, time=1612300276, title=None, item_type='comment', url=None, parent=26006214, text='Let&#x27;s say you currently have, for example, a few tools firing after a purchase:<p><pre><code>  fbq(&#x27;pay&#x27;, amount)\n  ga(&#x27;send&#x27;, { hitType: &#x27;event&#x27;, eventCategory: &#x27;Interaction&#x27;, eventAction: &#x27;Purchase&#x27;, eventLabel: amount });\n  ...\n</code></pre>\nYou would replace this whole block with<p><pre><code>  zaraz.track(&quot;payment&quot;, {amount})\n</code></pre>\nThis would make one request go from the browser to Zaraz, and Zaraz will handle it from there. It would work <i>without</i> loading fbevents.js, analytics.js, and other tool-specific JS files.<p>For HubSpot&#x27;s chat window we deliver a Facade (<a href="https:&#x2F;&#x2F;web.dev&#x2F;third-party-facades&#x2F;" rel="nofollow">https:&#x2F;&#x2F;web.dev&#x2F;third-party-facades&#x2F;</a>). Screen recording tools are harder to optimize, but we bundle their first JS with our response (saving a request for the browser), and we offer sampling them to only a percentage of your users (or based on some criteria, like not loading them for users with slow connections). We do this rules evaluation on our backend, unlike GTM and other tools that essentially are sending everything to all users and then evaluating things on the client side.')
