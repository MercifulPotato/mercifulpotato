Item(by='adamkl', descendants=None, kids=None, score=None, time=1612327959, title=None, item_type='comment', url=None, parent=26010307, text='<i>”Currently that runtime is a generic stateful &quot;service&quot; implementation provided by these libraries”</i><p>This is how I approached using XState in a proof of concept last year. I created a “service layer” made up of XState machines that handled different high-level aspects of the application behaviour; i.e. not tied specifically to a particular UI element. Things like managing the requests made during an OAuth flow and storing the authenticated user’s information.<p>This gave me a source of application state with well defined behaviours that I could use instead of “redux” and its usual accompaniment of boolean flags and thunks.<p>The best part of embracing the separation of state management from React is that I initially developed the application in Angular before lifting-and-shifting the “service layer” over to React and sticking in a “context”. All the application behaviours remained the same, it was just a matter wiring up some JSX in place of Angular’s HTML templates.')
